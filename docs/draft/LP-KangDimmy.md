## Bagian 1. Analisis & Struktur Layout

### 1.1 Posisi: perkenalan, bukan penawaran

Halaman ini berfungsi seperti **kartu nama yang bercerita**. Orang yang membuka tautan dari bio Instagram, LinkedIn, atau rekomendasi teman sedang bertanya "siapa orang ini?", bukan "berapa tarifnya?". Karena itu halaman menjawab pertanyaan pertama dengan baik, dan pintu menuju percakapan dibiarkan terbuka tanpa mendorong.

**Benang merah yang diceritakan:**
`Administrasi Publik → HR Manager → Public Relations → Public Speaking Trainer → Komunitas`

Pengalaman di sisi HR dan humas membuat Kang Dimmy memahami organisasi dari dalam. Hal ini disampaikan sebagai cerita (section Tentang), bukan sebagai keunggulan jual.

### 1.2 Prinsip soft selling

| Prinsip | Penerapan |
|---|---|
| **Cerita sebelum tawaran** | Tentang, Perjalanan, dan Aktivitas ada di depan; kontak di akhir |
| **Fakta, bukan klaim** | Tahun, kota, sektor, peran, organisasi. Tidak ada janji hasil |
| **Deskriptif, bukan transaksional** | Kartu bidang kerja tanpa tombol, tanpa harga, tanpa paket |
| **Satu pintu kontak** | Semua kontak di "Sapa Saya"; navbar hanya memuat tombol "Sapa Saya" |
| **Tanpa tekanan** | Tidak ada pop-up, bar melayang, penghitung, atau kata "sekarang" |
| **Bahasa orang pertama** | "Saya belajar…", "Saya berbagi…", bukan "Anda butuh…" |

### 1.3 Siapa mencari apa (tanpa memaksa jalur)

## Bagian 2. Rekomendasi UI/UX (neo-brutalism)

Spesifikasi lengkap (token, komponen, kode) ada di **`design.md`**. Ringkasan arahnya:

### 2.1 Karakter visual
**Berani, tetapi tertata. Hangat, bukan memaksa.** Referensi: gambar Blossom (kotak sorot kuning dengan garis penghubung, kartu bergaris bergaya bento, tombol hitam berbentuk pil, blok kuning penuh), lalu ditajamkan menjadi neo-brutalism.

| Ciri neo-brutalism | Penerapan |
|---|---|
| Garis tebal (2.5px) berwarna hitam | Semua kartu, tombol, chip, input |
| Bayangan keras tanpa blur (`6px 6px 0`) | Kartu dan tombol |
| Warna datar | Krem `#FBFAF4`, kuning `#FFE94A`, lavender `#CDBEFF`, hitam `#111111` |
| Tipografi tebal | Space Grotesk 700 untuk judul (H1 kapital), Inter untuk isi |
| Sorotan kata kunci | Kotak kuning bergaris di H1 (maks 2) |
| Stiker miring ringan | Hanya label kecil (lokasi, "Sekarang") |

### 2.2 Yang dijaga agar tetap profesional
- Jarak lega antar section (96–128px) dan lebar baris teks ≤ 66 karakter.
- Dua warna aksen per section, tidak lebih.
- Tidak ada mode gelap di fase 1, supaya identitas konsisten.
- Tidak ada avatar, rating, atau angka palsu seperti di mockup referensi.

### 2.3 Ritme warna antar section
Krem → **kuning (Sekilas)** → krem → krem-2 → krem → lavender muda (Aktivitas) → krem → **kuning (Sapa Saya)** → **hitam (footer)**.

### 2.4 Ajakan yang tenang
- Tombol hitam utama hanya satu di hero; di Sapa Saya tombol WhatsApp berwarna kuning.
- Tautan teks dengan efek stabilo kuning untuk ajakan kecil (Lihat semua aktivitas →, Ikuti →).
- Kartu bidang kerja tidak punya tombol.
- Tidak ada bar melayang atau pop-up.

### 2.5 Interactive CV (tetap)

| Fitur | Perilaku |
|---|---|
| Filter | Semua · Training · Komunitas & Relawan · PR & HR · Pendidikan |
| Accordion | Ringkasan satu baris, buka untuk detail |
| Unduh CV (PDF) | Satu klik, untuk yang membutuhkan arsip |
| Kotak "Sekilas" | Peran, tahun, jangkauan, pendidikan, domisili |
| Anchor per entri | `#motivacenter-2024` |
| Mode cetak | `@media print` bersih (tanpa bayangan) |

### 2.6 Performa, aksesibilitas, SEO
- LCP < 2.5 detik; gambar WebP/AVIF; halaman < 1.5 MB.
- Kontras AA, fokus keyboard terlihat, satu H1, alt text deskriptif.
- Skema `Person` (name A Dimmy Zulhifansyah, alternateName Kang Dimmy, jobTitle, Bandung, sameAs), Open Graph 1200×630, halaman detail aktivitas dapat diindeks.
- Analitik ringan (Plausible atau GA4): kedalaman scroll, pemutaran video, klik "Sapa Saya", pesan masuk.

### 2.7 Teknologi
**Astro + Tailwind CSS**, di-host di Cloudflare Pages atau Vercel (gratis), dengan Supabase sebagai data layer (Bagian 4). Astro menghasilkan halaman statis cepat dengan JavaScript minimal.

## Bagian 4. Activity System & Database

### 4.1 Kebutuhan dan Asumsi
Saya mengasumsikan "user bisa menyimpan data" berarti dua hal:
1. **Kang Dimmy (admin)** menambah, mengubah, dan menerbitkan aktivitas (judul, foto, tanggal, kota, tautan posting), yang langsung tampil di LP.
2. **Pengunjung** mengirim pesan lewat formulir "Sapa Saya" dan, bila diizinkan, testimoni. Data tersimpan di database dan baru tampil setelah disetujui admin.

Bila yang dimaksud adalah pengunjung yang bisa *menyimpan atau memberi bookmark* pada aktivitas, beri tahu saya; itu membutuhkan login pengunjung dan tabel tambahan.

### 4.2 Perbandingan Database Gratis
*Dicek dari halaman resmi dan ulasan pihak ketiga pada 26 Okt 2026. Batas gratis sering berubah, verifikasi lagi di halaman pricing sebelum memutuskan.*

| | **Supabase Free** | **Cloudflare D1 + R2** | **Neon Free** | **Firebase Spark** |
|---|---|---|---|---|
| Jenis | Postgres (SQL) | SQLite (SQL) | Postgres (SQL) | Firestore (NoSQL) |
| Kapasitas database | 500 MB per proyek | 500 MB per database, 5 GB per akun | 0,5–1 GB per proyek* | 1 GiB |
| Login admin bawaan | **Ya** (50.000 MAU) | Tidak | Tidak (perlu auth terpisah) | Ya (50.000 MAU) |
| Penyimpanan foto | **Ya**, 1 GB | R2 10 GB, tanpa biaya egress | Tidak bawaan | Cloud Storage tidak lagi di Spark sejak 2 Feb 2026 |
| Keamanan per baris (RLS) | **Ya** | Tidak (diatur di kode Worker) | Ya (Postgres) | Lewat Security Rules |
| Jika tidak ada trafik | **Proyek di-pause setelah 1 minggu tidak aktif** | Tidak pause | Scale-to-zero otomatis, bangun saat ada query | Tidak pause |
| Pembatas utama | 2 proyek aktif, egress 5 GB | Batas baca/tulis harian, ditegakkan sejak 1 Sep 2026 (≈5 juta baca, 100 ribu tulis per hari) | 100 CU-jam per proyek per bulan | 50 ribu baca, 20 ribu tulis per hari |
| Kecocokan untuk LP ini | **Terbaik secara keseluruhan** | Terbaik bila ingin selalu aktif dan tanpa pause | Baik bila hanya butuh database | Kurang cocok (NoSQL, tanpa storage gratis) |

\* Dokumentasi Neon menyebut 0,5 GB, tetapi pengumuman terbaru menyebut kenaikan ke 1 GB per proyek.

### 4.3 Rekomendasi
**Pilih Supabase (paket Free)** sebagai satu-satunya backend:
- Satu layanan memuat database Postgres, login admin, penyimpanan foto, dan RLS, sehingga tidak perlu membangun server sendiri.
- Skala data kecil: sekitar 5 aktivitas per pekan menghasilkan ±260 baris per tahun, jauh di bawah 500 MB.
- SQL standar. Bila suatu saat berpindah ke Neon atau server sendiri, datanya portabel.

**Risiko utama: auto-pause.** Proyek gratis dijeda setelah satu minggu tanpa aktivitas, dan sumber lain menyebut perlu dibuka manual. Mitigasi di 4.8.

**Alternatif bila ingin tanpa pause:** Cloudflare D1 + R2 (data dan foto) dengan admin dilindungi Cloudflare Access. Konsekuensinya Anda menulis lapisan API sendiri (Worker) dan tidak ada RLS bawaan. Lebih cocok bila ada developer.

### 4.4 Arsitektur

```
 Pengunjung ──► Halaman statis (Astro, Cloudflare Pages / Vercel)
                    │  baca aktivitas terbit (anon key + RLS)
                    ▼
              ┌───────────────┐        ┌────────────────────┐
              │   Supabase    │◄──────►│ /admin (hanya Kang │
              │ Postgres      │ login  │ Dimmy, link ajaib) │
              │ Auth · Storage│        └────────────────────┘
              └───────┬───────┘
 Formulir ► Turnstile ► Edge Function ► tabel inquiries ► notifikasi email/WA
                       │
          Webhook "terbit" ► rebuild situs statis (opsional)
```

Prinsip:
- **Statis dulu.** Halaman dibangun dari data saat build, sehingga LP tetap tampil walau database sedang di-pause. Database hanya dibutuhkan saat membangun ulang, saat admin menyimpan, dan saat formulir dikirim.
- **Anon key saja di browser.** Kunci `service_role` hanya di server/Edge Function, jangan pernah di kode frontend.
- **Tidak ada scraping otomatis** dari Instagram atau LinkedIn: tidak stabil dan berisiko melanggar ketentuan platform. Simpan tautan posting di kolom `source_url`, dan input dilakukan manual lewat form singkat.

### 4.5 Skema SQL (Supabase / Postgres)
Jalankan di SQL Editor Supabase, berurutan.

```sql
-- ============ ADMIN ============
create table public.admins (
  user_id uuid primary key references auth.users (id) on delete cascade
);
alter table public.admins enable row level security;  -- tanpa policy: tidak bisa diakses langsung

create or replace function public.is_admin()
returns boolean
language sql stable security definer
set search_path = ''
as $$
  select exists (
    select 1 from public.admins where user_id = (select auth.uid())
  );
$$;

create or replace function public.set_updated_at()
returns trigger
language plpgsql
set search_path = ''
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

-- ============ AKTIVITAS ============
create table public.activities (
  id            uuid primary key default gen_random_uuid(),
  slug          text unique not null check (slug ~ '^[a-z0-9]+(-[a-z0-9]+)*$'),
  title         text not null check (char_length(title) between 5 and 140),
  type          text not null check (type in
                  ('training','talk','coaching','community','content','achievement')),
  summary       text not null check (char_length(summary) <= 280),
  body_md       text,
  event_date    date not null,
  city          text,
  organizer     text,
  sector        text check (sector in ('korporasi','pemerintah','perbankan','fnb',
                  'organisasi','sekolah','universitas','pesantren','komunitas')),
  audience_size integer check (audience_size is null or audience_size >= 0),
  cover_url     text,
  gallery_urls  text[] not null default '{}',
  source_url    text,            -- tautan posting IG / LinkedIn / TikTok
  tags          text[] not null default '{}',
  is_featured   boolean not null default false,
  is_published  boolean not null default false,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);
create index activities_published_idx
  on public.activities (event_date desc) where is_published;
create index activities_type_idx on public.activities (type);
create trigger activities_updated_at before update on public.activities
  for each row execute function public.set_updated_at();

alter table public.activities enable row level security;
create policy "publik membaca yang terbit" on public.activities
  for select to anon, authenticated using (is_published);
create policy "admin penuh" on public.activities
  for all to authenticated
  using (public.is_admin()) with check (public.is_admin());

-- ============ PENGALAMAN (Interactive CV) ============
create table public.experiences (
  id           uuid primary key default gen_random_uuid(),
  category     text not null check (category in
                 ('training','community','pr_hr','education')),
  title        text not null,
  organization text not null,
  location     text,
  start_date   date not null,
  end_date     date,                    -- null = sampai sekarang
  summary      text,
  highlights   text[] not null default '{}',
  sort_order   integer not null default 0,
  is_published boolean not null default true,
  check (end_date is null or end_date >= start_date)
);
alter table public.experiences enable row level security;
create policy "publik membaca" on public.experiences
  for select to anon, authenticated using (is_published);
create policy "admin penuh" on public.experiences
  for all to authenticated
  using (public.is_admin()) with check (public.is_admin());

-- ============ TESTIMONI ============
create table public.testimonials (
  id            uuid primary key default gen_random_uuid(),
  author_name   text not null,
  author_role   text,
  organization  text,
  quote         text not null check (char_length(quote) between 20 and 500),
  consent       boolean not null default false,   -- izin ditampilkan
  is_approved   boolean not null default false,
  created_at    timestamptz not null default now()
);
alter table public.testimonials enable row level security;
create policy "publik membaca yang disetujui" on public.testimonials
  for select to anon, authenticated using (is_approved and consent);
create policy "pengunjung mengirim" on public.testimonials

-- ============ PESAN MASUK (formulir Sapa Saya) ============
create table public.inquiries (
  id           uuid primary key default gen_random_uuid(),
  name         text not null check (char_length(name) between 2 and 100),
  organization text,
  email        text,
  whatsapp     text,

                 ('kenalan','training','talk','coaching','community','other')),

  status       text not null default 'new' check (status in ('new','replied','closed')),
  created_at   timestamptz not null default now(),
  check (email is not null or whatsapp is not null)
);
alter table public.inquiries enable row level security;
create policy "pengunjung mengirim" on public.inquiries

with (security_invoker = true) as
select
  count(*) filter (where type in ('training','talk','coaching')) as total_sessions,
  count(distinct city) filter (where city is not null)           as total_cities,
```

### 4.8 Mencegah Proyek Di-pause
Supabase menjeda proyek gratis setelah seminggu tanpa aktivitas. Dua lapis perlindungan:
1. **Situs statis** (4.4), jadi pengunjung tidak terdampak.
2. **Ping terjadwal** dua kali seminggu lewat GitHub Actions:

```yaml
name: keep-supabase-awake
on:
  schedule:
    - cron: "0 3 * * 1,4"      # Senin dan Kamis, 03:00 UTC
  workflow_dispatch:
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -fsS "$SUPABASE_URL/rest/v1/site_settings?select=key&limit=1" \
            -H "apikey: $SUPABASE_ANON_KEY" \
            -H "Authorization: Bearer $SUPABASE_ANON_KEY"
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_ANON_KEY: ${{ secrets.SUPABASE_ANON_KEY }}
```
Catatan: GitHub dapat menonaktifkan jadwal di repositori yang lama tidak aktif, dan Supabase dapat mengubah definisi "aktif". Cek status proyek sebulan sekali. Jika pause tetap mengganggu, pindahkan ke Cloudflare D1 + R2 (4.3) atau naikkan ke paket berbayar Supabase.

### 4.9 Perkiraan Kapasitas (asumsi 5 aktivitas per pekan, 5 foto per aktivitas)

| Sumber daya | Perkiraan pemakaian | Batas gratis | Cukup untuk |
|---|---|---|---|
| Baris database | ±260 aktivitas per tahun, ±1 MB per tahun | 500 MB | Puluhan tahun |
| Foto (WebP ≤ 200 KB × 5) | ±260 MB per tahun | 1 GB | ±4 tahun |
| Trafik keluar | rata-rata 300 KB per halaman | 5 GB per bulan | Belasan ribu kunjungan per bulan sebelum cache |

Bila foto mendekati batas atau ada lonjakan trafik (misalnya Reels viral), pindahkan foto ke Cloudflare R2 (10 GB, tanpa biaya egress) dan simpan hanya URL di `cover_url` serta `gallery_urls`. Struktur tabel tidak perlu berubah. Menaruh Cloudflare sebagai CDN di depan situs juga mengurangi egress.
